# R0.1 Seat model + value relabel: design

Source: [ROLLOUT-ROADMAP.md](ROLLOUT-ROADMAP.md) R0.1. Rewritten 2026-11-21 from
[BurnWatch-Rollout-Proposal.md](BurnWatch-Rollout-Proposal.md) section 7, because the
original spec (`docs/superpowers/specs/2026-11-16-seat-billing-design.md`) was never
committed. Status: reviewed 2026-11-21. Limit-hit counting is in R0.1 (moved forward from R0.3);
value multiple uses total value ÷ actual cost; two sessions.

## Why

Under seat billing the company pays a fixed fee per seat. The `$` the dashboard shows is
what the same usage would cost at API list prices. Calling it "spend" makes heavy users
look expensive when they get the most out of a fixed fee.

## Terms

| Term | Meaning |
|---|---|
| **Value** | Today's `totalCostMicros`: usage priced at API list prices. Every agent, seated or not. |
| **Seat cost** | Sum of seat prices, prorated by day over the range. |
| **API spend** | Value of usage on agents the user has no seat for. Real money on an API key. |
| **Actual cost** | Seat cost + API spend. |
| **Value multiple** | Value ÷ actual cost. `null` when actual cost is 0. |

Heavy API-key usage pulls the multiple toward 1×. That is intended: it shows the
user is paying list price for that share.

## Data model (`packages/db`)

```ts
type SeatKey = `${UserId}:${AgentName}`

interface SeatDoc {
  _id: SeatKey                  // one seat per (user, agent); duplicate add is an upsert
  orgId: OrgId
  userId: UserId
  agent: AgentName
  monthlyPriceMicros: Micros
  startDate: IsoDate            // form default: first day of the current month
  createdAt: Date
}
```

Index: `seats_org_agent` `{ orgId: 1, agent: 1 }`. Readers: admin list, seat cost and
idle-seat checks, all per org.

No migration for `seats`: it starts empty and `syncSchema` creates it from the registry.

### Budget alert `type`

```ts
interface BudgetAlertDoc {
  // ...existing fields
  type: 'api-spend' | 'idle-seat' | 'limit-hit'
  /** idle-seat only. */
  idleDays: number | null
  /** limit-hit only: hits this month that trip the alert. */
  limitHits: number | null
}
```

- `api-spend`: existing behaviour, but month-to-date spend counts only unseated usage.
  `monthlyLimitMicros` and `threshold` apply only to this type.
- `idle-seat`: trips when any seat in scope (org, or one user; one agent or all) has had
  no tokens for its agent in the last `idleDays` days. Seats younger than `idleDays` do
  not count.
- `limit-hit`: trips when Claude usage-limit hits in scope reach `limitHits` this month.
  Reads `limitHitCount` from Claude enrichment. Days synced by an older agent read as 0.

Migration `0002_budget_alert_type` sets `type: 'api-spend', idleDays: null, limitHits: null` on every
alert missing `type`. Idempotent: it matches `{ type: { $exists: false } }`.

### Limit-hit counting (agent)

The agent's collectors (`ccusage`, `codeburn`) do not expose limit hits, so the agent
reads Claude transcripts directly: `~/.claude/projects/**/*.jsonl`.

- A hit is an assistant message whose text matches Claude Code's usage-limit notice
  (e.g. `Claude AI usage limit reached`, `5-hour limit reached`). Exact patterns are
  confirmed against real transcripts on this Mac before coding.
- Counted per local day of the message timestamp, deduplicated by message text per day,
  because one limit can be echoed across resumed sessions.
- Sent as optional `limitHitCount` on the Claude enrichment payload.
  `ClaudeEnrichmentDoc.limitHitCount: number | null`; older agents send nothing → `null`.
- Only the count leaves the machine. No message text is sent.
- Ships as agent `0.3.0`. Older agents keep working.

## Seat cost formula

Per seat, over range `[from, to]`:

```
days = overlap([from, to], [startDate, today])   // 0 if none
seatCost = round(monthlyPriceMicros * 12 / 365 * days)
```

- Daily rate is `monthly × 12 ÷ 365`, so 365 days of seat equals 12 months of price.
- Capped at today, so the "All time" range (from `2020-01-01`) does not bill seven years.
- No end date. Removing the seat removes its history too (known limit).

Computed in TypeScript from the seat rows, not in the pipeline. Seat count is small (one
org's developers × agents), and the date math is clearer in code.

## API (`apps/api`)

Seats routes, admin only, under `/v1/dashboard`:

| Route | Does |
|---|---|
| `GET /seats` | All seats in the org, with user name and email. |
| `PUT /seats/:userId/:agent` | Upsert `{ monthlyPriceUsd, startDate }`. User must be in the caller's org. |
| `DELETE /seats/:userId/:agent` | Remove one seat. |
| `POST /seats/assign-all` | `{ agent, monthlyPriceUsd, startDate }`. Inserts a seat for every active user without one for that agent. Never overwrites. Returns `{ created }`. |

Every seat write re-evaluates the org's `api-spend` and `idle-seat` alerts in the same
transaction, because it changes which usage counts as API spend.

Response changes (all additive, older dashboards keep working):

- **Overview:** `valueUsd` (same number as today's `totalCostUsd`, kept for one release),
  `actualCost: { seatUsd, apiUsd, totalUsd, seatCount, monthlySeatUsd }`. Scope rules
  from R0.2 apply: a manager's figures cover only their scope's seats.
- **Leaderboard entry:** `actualCostUsd`, `apiSpendUsd`, `valueMultiple: number | null`.
  Sort stays on value for this release. A8 changes the ranking in R1.
- **Budget alerts:** `type`, `idleDays`, and for `idle-seat` the list of idle seats.

`monthToDateSpend` gains a `seated: Set<SeatKey>` argument and sums only unseated
`(user, agent)` pairs. It has one caller (`applyTrip`), so the change stays local.

## Decisions to review

1. **Seat cost is prorated by day**, from start date, capped at today.
2. **"Assign to everyone" is non-destructive.** Fills gaps, never overwrites. Re-run it
   when someone joins.
3. **Seat writes re-check alerts** in the same transaction.
4. **Seat count means seat rows.** Claude + Copilot for one person is two seats. Seats of
   deactivated users cost money until removed; the idle-seat alert flags them.
5. **Idle is per agent.** A Claude seat is idle when that user has no Claude tokens for
   `idleDays`.
6. **Limit-hit counting ships in R0.1** as agent 0.3.0. Claude only. No server-side
   backfill: old days read 0 until a developer re-syncs with the new agent.
7. **Copilot integration seats stay separate.** BW-21 reads seats from GitHub but is
   unverified against a real org. Admins enter Copilot seats here by hand for now.
8. **Value multiple is value ÷ actual cost** (see Terms).
9. **Terminology changes everywhere** in one pass (Trends, Projects, Admin, charts).

## Known limits

- A seat has no end date. Removing it rewrites history.
- Usage before a seat's start date still counts as seated (not API spend).
- Org fact #1 (plan tiers and prices) is data, not code. Admins enter it after deploy.

## Session A review (2026-11-21)

Typecheck and all suites pass (shared 36, db 55, api 491, dashboard 126, agent 83);
`dashboard-pipelines` PASS 36 checks on a local replica set. Deviations from the spec:

- `SeatKey` is a branded string from `seatKey()`, matching the other keys in `ids.ts`.
- `monthToDateSpend` takes a required `seated` set; it has two callers (alert service and
  GET budget-alerts), not one.
- Non-api-spend alerts store `monthlyLimitMicros: 0`. A request without `type` is api-spend.
- `BudgetAlertInput`/`Patch` types are `z.input`, so the dashboard compiles unchanged.
- Limit-hit alerts ignore `agent` (Claude only). `seatCount` ignores the date range.
- Limit-hit dates are UTC, like the rest of codeburn's enrichment.
- Notice wording comes from the Claude Code CLI 2.1.330 bundle: no transcript on the dev
  Mac has a real notice. Match: `isApiErrorMessage` + `/You've hit your .*limit|limit reached/i`.
  May over-count other "limit reached" API errors.
