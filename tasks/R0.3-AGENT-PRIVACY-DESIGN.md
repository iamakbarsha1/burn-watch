# R0.3 Agent v0.4.0: path privacy + transcript fields: design

Source: [ROLLOUT-ROADMAP.md](ROLLOUT-ROADMAP.md) R0.3 and
[BurnWatch-Rollout-Proposal.md](BurnWatch-Rollout-Proposal.md) (path privacy row, A5, B5,
B6, C1, C4). Status: reviewed 2026-11-21. All 11 decisions accepted as recommended (user confirmed 1, 4, 6, 7 explicitly). Ships as agent `0.4.0`.

## Why

The agent sends absolute paths such as `/Users/<name>/code/<client-repo>` and the
dashboard prints them. That leaks user names and client folder names, and it gives C1
nothing stable to match on. R2 (A5, B5, B6, C4) needs fields that sit in Claude
transcripts today but are not collected. One agent release does both.

## What the transcripts hold (this Mac, 178 files, 2026-11-21)

Key names and value types only. Counts are records.

| Field | Where | Type | Present |
|---|---|---|---|
| `isSidechain` | top-level on `user`, `assistant`, `system`, `attachment` | bool | every such record (24,297); true on 3,302 |
| `entrypoint` | same records | string | every such record; values `cli`, `sdk-ts` |
| `version` | same records, plus `api-request*` | string | every such record; all `2.x` |
| `gitBranch` | same records | string | every such record; `HEAD` when detached (1,187) |
| `cwd` | same records | string | every such record |
| `attributionSkill` | top-level on `assistant` only | string | 538 of 7,766 assistant records, 15 files, 4 distinct values |
| `permissionMode` | top-level on `user` (432 of 4,355) and on `permission-mode` records (356) | string | values seen: `bypassPermissions`, `plan`, `dontAsk` |
| `accountUuid` | `session-owner` records only (1,587), with `organizationUuid` and `sessionId` | string | 47 files |

All seven exist. Two need care:

- `session-owner` and `permission-mode` records carry **no timestamp**. `accountUuid`
  must be joined to days through `sessionId`. `permissionMode` is read from `user`
  records, which do have a timestamp.
- `gitBranch` and `cwd` are per record, not per session: 8 of 156 sessions span more
  than one branch, 29 span more than one cwd.

Subagent transcripts live one level deeper (`<project>/<session>/subagents/*.jsonl`, 21
files). `findJsonlFiles` already recurses into them.

Remotes on this Mac: 18 distinct cwds fold into 5 roots; 3 are Git repos, 2 are not.
All 3 remotes are scp-style SSH with a host alias (`git@github.com-<alias>:org/repo.git`).
Plain string normalisation would report the alias, not `github.com`.

## Wire changes (`packages/shared`)

All additive and optional, so 0.3 agents keep working, and a 0.4 agent against an old
server has the new keys stripped by `z.object`.

```ts
ProjectEntrySchema = z.object({
  path: z.string().min(1),          // meaning changes: repo name, never a path
  remote: z.string().max(300).nullable().optional(),   // normalised, see below
  branches: z.array(z.object({ name: z.string().max(200), cost, sessions })).max(50).optional(),
  cost, avgPerSession, sessions, overheadK,             // unchanged
})

ClaudeEnrichmentSchema.extend({
  claudeVersions: z.record(z.string(), count).optional(),    // assistant msgs per Claude Code version
  entrypointCounts: z.record(z.string(), count).optional(),  // assistant msgs per entrypoint
  skillCounts: z.record(z.string(), count).optional(),       // assistant msgs per attributionSkill
  sidechainMessages: count.optional(),                       // assistant msgs with isSidechain
  permissionModeCounts: z.record(z.string(), count).optional(), // user prompts per mode; no view (B4)
  accountHashes: z.array(z.string().length(64)).max(20).optional(), // hashed accountUuid, distinct per day
})
```

- `path` keeps its name so 0.3 agents still validate. The schema gets `.describe()` text
  on every enrichment field, including `path` ("repository name, not a path").
- `types.ts` drops its hand-written `ProjectEntry`, `SessionEntry` and `ClaudeEnrichment`
  and re-exports `z.infer` of the schemas. R0.4 renders the field list and the
  `.describe()` text from the schema. Nothing else lists fields.

### How R2 reads them

| Item | Reads | Why this shape |
|---|---|---|
| B5 version per device | `DeviceDoc.claudeVersion` | Enrichment is keyed per user per day (`dayKey`), so two devices overwrite each other. Submit (`submit.ts:119`, already updates the device) also sets `claudeVersion` to the highest key in `claudeVersions`. |
| A5 feature matrix | `skillCounts`, `sidechainMessages`, `permissionModeCounts.plan`, `entrypointCounts`, plus existing `mcpUsage` | "Used X this period" is `sum > 0` per user; counts also allow share-of-messages. |
| B6 account vs seat | `accountHashes` | Same hash under two users means a shared account. A user with several hashes, or a hash no seated user has, flags a second account. |
| C4 ticket keys | `projectBreakdown[].branches` | Ticket key is parsed server-side from `name`; cost per branch gives usage per ticket. Per repo, so `main` in two repos stays apart. |

## Agent (`apps/agent`)

### Repo identity

Per distinct root (already memoised in `projectRoot`):

1. `remote = git -C <root> remote get-url origin` (execFile, 5 s timeout, same PATH fix as
   `withCommandDirOnPath`). `get-url` applies `insteadOf` rewrites and handles worktrees,
   which parsing `.git/config` would not.
2. `normaliseRemote(url)`:
   - scp form `user@host:path` and URL forms (`ssh://`, `https://`, `git://`) both become
     `host/path`. Userinfo (tokens in https URLs), port and trailing `.git` and `/` are dropped.
   - SSH host aliases resolve through `ssh -G <host>` (reads `~/.ssh/config`, prints
     `hostname`). Cached per host. If ssh fails, keep the alias.
   - Lowercased. `git@github.com:Org/Repo.git`, `https://tok@github.com/org/repo` and
     `git@github.com-work:org/repo.git` all give `github.com/org/repo`.
   - Local remotes (`/srv/x.git`, `file://`) give `null`: they are paths.
3. `path` (repo name) = last segment of the normalised remote; else basename of the root.
   A root equal to the home directory becomes `~`, because its basename is the user name.
4. No remote, Git missing, or the folder gone: `remote: null`, name from the basename of
   what `projectRoot` returned. A gone subfolder reports its own basename (known limit).

Project buckets are keyed by `remote ?? name`, so two clones of one repo merge on device.

### New fields

Same single pass in `collectRange`:

- Assistant records: count `version`, `entrypoint`, `attributionSkill` (when set),
  `isSidechain === true`; add tokens per `gitBranch` to the record's project bucket
  (skip empty and `HEAD`). Branch cost uses the same token-share split as projects.
- `user` records with `permissionMode`: count per mode for the record's day.
- `session-owner` records: `sessionId → accountUuid` map. After the pass, each day's
  `accountHashes` is the distinct hashes of the sessions in `b.sessions`.
- Hash: `HMAC-SHA256(key = config.orgId, accountUuid)`, hex. Raw `accountUuid` never
  leaves the machine.

Only counts, names already shown in Claude Code's UI (versions, modes, skill names,
branch names) and hashes leave the machine. No prompt or code text.

## API + db

- `upsertEnrichment` (`usage.ts:114`) stores the new fields, `null` when absent, as
  `limitHitCount` does. It also strips `path` to its last segment (`/` or `\`) on every
  write, so a 0.3 agent cannot store a new absolute path after deploy.
- `ClaudeEnrichmentDoc` gains the fields as `... | null`. `DeviceDoc` gains
  `claudeVersion: string | null`.
- `projectTotals` groups on `{ $ifNull: ['$projectBreakdown.remote', '$projectBreakdown.path'] }`
  and returns `path` (name) and `remote`. `OrgProjectSummary` gains `remote: string | null`.
- No route for any new field in R0.3. R2 builds the views.

### Stored paths in prod

| Option | Effort | Risk |
|---|---|---|
| (a) Migration `0003_project_path_basename`: one `updateMany` pipeline, `$map` over `projectBreakdown` setting `path` to the last segment; home-folder paths (`/Users/x`, `/home/x`, `C:\Users\x`) become `~`. Idempotent: a basename maps to itself. | S: about 30 lines plus test | Irreversible. History of two repos with the same folder name merges into one row. |
| (b) Leave history, change going forward | none | Every range before the upgrade keeps showing absolute paths. Contradicts "agent v0.4 sends no absolute paths" and the R0.4 page. |
| (c) Set `projectBreakdown: null` on all history | XS | Loses all per-project history. More loss than the problem needs. |

Recommend (a), plus the write-time strip. Take an Atlas snapshot first.

## Decisions to review

1. **Stored paths: migration to basename (option a)** plus server strip on every write.
2. **Keep the wire name `path`**, redefined as repo name, so 0.3 agents still validate.
   Rename to `repo` in a later breaking release if ever.
3. **Group projects by normalised remote, fall back to name.** Grouping by name alone
   would merge every org's `api` and `web` repos.
4. **Resolve SSH host aliases with `ssh -G`.** Without it, C1 patterns like
   `github.com/<client-org>/*` miss every aliased clone, which is all of them on this Mac.
5. **Run `git remote get-url origin`** per root, not parse `.git/config`. `origin` only.
6. **Hash `accountUuid` with HMAC keyed on `orgId`.** Stable across every device in the
   org, so B6 works; different per org, so hashes cannot be linked across tenants. Not a
   secret from anyone holding the DB, and that is fine: the aim is not storing the raw ID.
   No salt would link across tenants; a per-device salt would break B6.
7. **Also send hashed `organizationUuid`** (same record, same HMAC) as `claudeOrgHashes`.
   B6's "personal account" check needs it: a session-owner outside the company's Claude
   org is the signal. Not in the roadmap list; add it only if approved.
8. **Full branch names, parsed server-side** for C4. Sending only extracted ticket keys
   would tie the agent to one key format.
9. **Claude Code version per device on `DeviceDoc`** set at submit, because enrichment is
   per user per day.
10. **Report agent version on submit.** `DeviceDoc.agentVersion` is set at register
    (`apps/api/src/routes/auth/device.ts:189`, `:314`) and never updated, so "share of devices
    on 0.4" (roadmap R2 entry rule) cannot be measured. Add optional `agentVersion` to
    `UsagePayloadSchema`; submit writes it to the device. Recommend yes.
11. **`types.ts` re-exports `z.infer`** and fields get `.describe()`, so the Zod schema
    is the one list R0.4 reads.

## Known limits

- Per-record counts use assistant messages, as `callCount` does; `permissionModeCounts`
  uses user prompts. Only 432 of 4,355 user records carry `permissionMode`; which ones
  is confirmed on fixtures in Session A. `default` / `acceptEdits` strings were not seen
  on this Mac.
- `session-owner` appears in 47 of 178 files. Older sessions give no `accountHashes`.
- A gone subfolder cwd reports its own basename, not the repo's.
- Repos without `origin` (or only another remote) get `remote: null`.
- Two devices of one user on the same day still overwrite each other's enrichment
  (existing `dayKey` limit).
- History before the upgrade has names but no remotes, so a repo can show twice in a
  range that straddles the upgrade (once by name, once by remote).
- Record keys with `.` (versions like `2.1.330`, skill names) are stored as field names.
  `shellUsage` already does this. Session A confirms writes and `$objectToArray` reads
  on the local replica set.
- Old absolute paths remain in Atlas backups until they expire and in the retained Neon
  dump (`~/Backups/burn-watch/`) until Neon is retired.

## Tests

  `.git` and `/`, mixed case, alias resolved, alias unresolvable, local path gives `null`.

  sums to project cost; `session-owner` with no timestamp joined by `sessionId`; raw

## Session A review (2026-11-21)

Typecheck and all suites pass (shared 40, db 66, api 493, dashboard 154, agent 109).
`dashboard-pipelines` PASS 37 checks on a local replica set, including two `api` repos with
different remotes staying two rows. Migration `0003` on the local set gave
`repo`, `~`, `y`, `plain` and was unchanged on a second run.
Migration `0004` folds `shellUsage` path keys to the command name with the write path's
`commandNames`, summing collisions. On the local set `/usr/bin/git: 3` + `git: 5` gave `git: 8`,
non-path keys and null `shellUsage` were untouched, and a second run changed nothing.

Dry run of the collector on this Mac's transcripts (last 31 days, real `git` and `ssh -G`):
5 days, every payload passes `UsagePayloadSchema`, no value or key contains `/Users/` or
starts with `/`, no raw `accountUuid` or `organizationUuid` in the payload. 3 remotes, all
`github.com/...`, none left as a host alias. The previous collector was not run (events carry model and
token counts only).

Dotted keys: Mongo 8.0 stores keys like `2.1.330` as field names. `$set` of the whole map,
insert, `$objectToArray` and `$getField` all work; only a dot-path query
(`claudeVersions.2.1.330`) cannot address them. Every write sets the whole map and every
read goes through `$objectToArray`, so the maps stay records. No encoding.

Deviations from the spec:

- The dry run found a leak outside the new fields: `shellUsage` is keyed by a command's
  first word, so a command run by absolute path sent the path (2 keys on this Mac). The
  agent now sends the basename, and `upsertEnrichment` folds `shellUsage` keys to their
  basename on write, so 0.3 agents are covered too.
- Migration `0003` is a cursor plus `bulkWrite` in batches of 500, not an `updateMany`
  pipeline, so it shares `repoName` with the write path. Each update filters on `_id` and
  `submittedAt`, so a day re-synced mid-run keeps its newer breakdown.
- The write-time strip uses the same `repoName`: home folders become `~`, as in the
  migration. It also strips `topSessions[].project`.
- `claudeOrgHashes` is sent (decision 7).
- Repo identity is resolved during the pass, memoised per root, so project buckets are keyed
  by `remote ?? name` from the start and need no merge step. `git` runs only when the root
  has a `.git`, so a gone or non-repo folder never spawns it.
- `git` and `ssh` are called by bare name. `withCommandDirOnPath` is a no-op for a bare
  name, so there is no PATH change; both live in `/usr/bin` on macOS and Linux.
- `ssh -G` is only given plain host names (no leading `-`). A remote over 300 characters
  is sent as `null`. Branch names are cut at 200 characters; the top 50 branches by cost
  are kept.
- New maps and hash arrays are sent empty (`{}`, `[]`) rather than left out when a day has
  none. No hashes are sent when the collector has no `orgId` (tests only; `sync` passes
  the config's).
- `permissionMode` sits only on user prompts (string or text content), never on tool
  results: 438 records on this Mac.
- Device versions: `agentVersion` and `claudeVersion` are set only when sent; the highest
  version uses numeric collation (`2.1.330` above `2.1.99`).
- Projects rows are keyed `remote ?? path` in the dashboard, since two repos can share a name.
- `ActivityEntry` stays hand-written in `types.ts`; only the three types named here moved.

Open:

- Historical `shellUsage` keys in Atlas can still hold absolute paths. `0003` only covers
  `projectBreakdown`. A follow-up migration could fold them like the write path does.
- `0003` and the device version writes were tested on fakes and the local set only.

Before release: Atlas snapshot, `db:migrate` for `0003`, then tag `v0.4.0`.
