# R0.2 Teams + manager scope (with C5): design

Source: [ROLLOUT-ROADMAP.md](ROLLOUT-ROADMAP.md) R0.2. Status: API and dashboard UI done on `feat/r0.2-teams` (uncommitted).

Decisions confirmed 2026-11-18: role on membership; compare open to admins and
managers; bad `teamId` answers 403; API and UI in separate sessions.

## Rule

| Role (JWT) | Sees |
|---|---|
| admin | whole org |
| manager | self + every member of each team they manage |
| developer | self |

A `manager` JWT role with no managed team sees only self. A team `manager`
membership row on a `developer` or `admin` user changes nothing for that user:
the JWT role is the gate, the membership rows only widen a manager.

## Data model (`packages/db`)

```ts
interface TeamDoc {
  _id: TeamId            // newId()
  orgId: OrgId
  name: string           // unique per org
  createdAt: Date
}

interface TeamMemberDoc {
  _id: TeamMemberKey     // `${teamId}:${userId}`, so a duplicate add is a no-op upsert
  teamId: TeamId
  orgId: OrgId           // denormalised, same reason as UsageEventDoc
  userId: UserId
  role: 'manager' | 'member'
  createdAt: Date
}
```

Indexes (each has a reader):

- `teams_org_name` `{ orgId: 1, name: 1 }` unique: list teams, block duplicate names.
- `teamMembers_user_role` `{ userId: 1, role: 1 }`: viewerScope looks up "teams I manage" on every dashboard request.
- `teamMembers_team` `{ teamId: 1 }`: load members of a team (scope, filter, compare).

Many-to-many: a user can be in more than one team, and a team can have more
than one manager. Team totals in C5 can then overlap, and the page says so.

No migration: both collections start empty. `syncSchema` creates them from the
registry entry.

## viewerScope

`apps/api/src/plugins/jwt.ts`:

```ts
// undefined = whole org. Otherwise the user ids the viewer may read.
export async function viewerScope(user: JwtPayload): Promise<UserId[] | undefined>
```

- admin: `undefined`
- developer: `[user.userId]`
- manager: `[user.userId, ...members of teams where (userId, role 'manager')]`, deduped.
  Two reads: `teamMembers.find({ userId, orgId, role: 'manager' })` then
  `teamMembers.find({ orgId, teamId: { $in } })`. `orgId` on both so a forged
  row in another org cannot widen scope.

Every pipeline changes `...(userId && { userId })` to
`...(ids && { userId: { $in: ids } })`. Seven call sites: overview, trends,
leaderboard, activity (`enrichmentMatch`), projects, budget-alerts GET.

Budget alerts: non-admins see only alerts whose `userId` is in scope, as today.
Org-wide alerts (`userId: null`) stay admin-only.

## Team filter (Overview, Trends)

New optional query param `teamId` on `/overview` and `/trends`.

`readScope(user, teamId)` (in `jwt.ts`, calls `teamScope`):

1. No `teamId`: `viewerScope(user)`.
2. `teamId` given: load team by `{ _id: teamId, orgId }`. Missing: 404.
   Members of that team, intersected with `viewerScope(user)`.
   A manager filtering to a team they do not manage gets 403, not an empty
   intersection, so the UI cannot silently show zeros.
   A developer may only pass a team they belong to; result is still `[self]`.

## C5 team comparison

`GET /v1/dashboard/teams/compare?from&to`

- admin: every team in the org. manager: teams they manage. developer: 403.
- One `dailySnapshots` aggregate over the union of member ids, then group per
  team in the route (member map is small, at most a few hundred users).
- Response per team: `{ teamId, name, memberCount, activeUsers, totalCostUsd,
  totalTokens, byAgent: AgentSummary[], daily: { date, totalCost }[] }`.

Dashboard: Overview gets a "Teams" table (cost, tokens, active/members),
Trends gets one line per team. Shown only when the viewer can see 2+ teams.

## Team management (admin only)

Needed because admins enter the team list in the UI after ship.

- `GET    /v1/dashboard/teams`: teams visible to the viewer, with members.
- `POST   /v1/dashboard/teams` `{ name }`: admin.
- `PATCH  /v1/dashboard/teams/:id` `{ name }`: admin.
- `DELETE /v1/dashboard/teams/:id`: admin, deletes its member rows too.
- `PUT    /v1/dashboard/teams/:id/members/:userId` `{ role }`: admin. Checks
  the user is in the caller's org (same check budget-alerts POST does).
- `DELETE /v1/dashboard/teams/:id/members/:userId`: admin.

Admin page: a Teams panel next to Budget alerts: create, rename, delete, add a
member from the org user list, toggle manager.

## Known limits (not fixed here)

- JWT role lives 30 days. Promoting someone to `manager` takes effect on their
  next login or refresh. Team membership changes apply on the next request,
  since scope is read per request.
- Leaderboard, Activity, Projects get manager scope but no team filter.
  Add it when A3/A5 need it.
- "$" relabel to API-equivalent value is R0.1, not here.

## Tests

`apps/api/src/routes/routes.test.ts`, extending "viewer scoping":

- developer: every route's match has `userId: { $in: [USER_A] }`.
- manager with no teams: same as developer.
- manager of team T (members A, B): match has `$in` with both, nothing else.
- manager passes `teamId` of a team they do not manage: 403.
- unknown `teamId`: 404. `teamId` from another org: 404 (team lookup filters orgId).
- admin: no `userId` in any match; with `teamId`, `$in` of that team only.
- compare: developer 403; manager sees only managed teams.
- team CRUD: non-admin 403; member add with a user from another org: 400.

Unit test for `viewerScope` covering each role and the dedupe.
